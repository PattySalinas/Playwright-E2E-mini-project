HL_Verify a new todo can be added to the list
------------------------------------------------------------------------
Summary:
  Validates the core "add todo" happy path. A user types a task into the
  main input and presses Enter. This is the foundational functionality of
  the app and is exercised in the existing tests/todo.spec.ts sanity test.
  The new-todo field carries data-testid="text-input".

Tags: functional, happy-path, todo-creation, Regression

Steps:
  1. Action: Navigate to https://todomvc.com/examples/react/dist/
     Expected: The app should load and the "What needs to be done?" input
               should be visible and empty.
  2. Action: Type "Buy groceries" into the new-todo input and press Enter.
     Expected: The system should add "Buy groceries" as a new item in the
               todo list and should clear the input field.
  3. Action: Observe the todo counter.
     Expected: The system should display "1 item left".

HL_Verify an empty or whitespace-only todo is not added
------------------------------------------------------------------------
Summary:
  Negative/edge case for the add-todo input boundary. Submitting an empty
  string or only spaces should not create a list item. Covers the
  user-input boundary required by the standards.

Tags: functional, negative, Edge Case, todo-creation

Steps:
  1. Action: Navigate to the app.
     Expected: The app should load with an empty todo list.
  2. Action: Focus the new-todo input, press Enter without typing.
     Expected: The system should not add any item and the list should
               remain empty.
  3. Action: Type only spaces "   " and press Enter.
     Expected: The system should not add a whitespace-only item and the
               list should remain empty.


------------------------------------------------------------------------
HL_Verify todos are not persisted after a page reload
------------------------------------------------------------------------
Summary:
  Negative/edge case documenting that THIS TodoMVC React build does NOT
  implement client-side persistence. Verified with the Playwright MCP:
  after adding todos, localStorage remains empty and the todos are lost on
  reload. This test intentionally asserts the ABSENCE of persistence so the
  behavior is captured and regressions (in either direction) are caught.

Tags: functional, negative, Edge Case, persistence

Steps:
  1. Action: Navigate to the app and add "Buy groceries" and "Pay bills".
     Expected: The system should display both items in the todo list.
  2. Action: Reload the page.
     Expected: The system should NOT restore the todos; the list should be
               empty and the "items left" counter should not be shown.
